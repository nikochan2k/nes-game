# OSM ベクターデータ → NES 地形 変換プラン

現状は `server/mapserver.ts` の `SyntheticSource` がノイズで作った仮の世界を返している。
これを日本全国の実際の地図に置き換える。

方針は次のとおり。

- 地図からマスを**その場で作るのではなく**、OSM のベクターデータから**事前に**作る。
- 事前に作るのは **z18 のマスだけ**。NES の地形 ID ではなく、OSM の種別を属性として SQLite に格納する。
- z17 以下のマスと NES の地形 ID は、リクエスト(z/x/y)ごとに SQLite から**動的に**作る。
- 山・岩山の判定には、国土地理院の標高データ(DEM)を併用する。

未決事項は「10. 決めたいこと」にまとめた。

## 1. 前提(いまのコードが決めていること)

- 世界の 1 辺は 2^(z+4) マス。1 タイル(256px)= 16×16 マスで、**1 マス = タイル上の 16×16px**。
- NES に返すのは 1 マス 1 バイトの地形 ID。サーバーの入口は `answer()` で、
  リクエストは「z、マス座標 (x, y)、縦/横、個数 n」の 1 行または 1 列(`decode_request()`)。
  差し替えるのは `SyntheticSource.cell(z, x, y)` の部分。
- 現在の地形 ID は 10 種(`src/terrain.h`):草原・森・山・岩山・水・橋(横/縦)・道路(横/縦/交差点)。
- 通行不可は水と岩山のみ(`src/main.c` の `probe_run`)。
- NES の応答待ちは約 0.35 秒(`src/link.c` の `WAIT_CLOCKS`)。超えると以後はサーバーを使わなくなる。
- 実機の制約:BG のパターンテーブルは 4KB(64 メタタイル)、BG パレットは 4 つ、1 マスにつき 1 パレット。

## 2. 全体像

```
[事前ビルド]  (一度だけ。数時間)
  OSM (japan-latest.osm.pbf) ─┐
  海岸線 (land polygons)     ─┼─→ z18 のマスにラスタライズ ─→ data/world.sqlite
  標高 (DEM10B)              ─┘     (OSM 種別 + 傾斜を格納)

[実行時]  (リクエストごと)
  NES ──(z, x, y, 縦/横, n)──→ answer()
                                └ OsmSource
                                    ├ 必要なブロックを SQLite から読む(LRU キャッシュ)
                                    ├ z18 のマスを z に合わせて集約
                                    ├ OSM 種別 → 地形を決定、道路・線路の向きを決定
                                    └ NES の地形 ID を返す
```

## 3. z18 のマスの大きさと容量

| 項目 | 値 |
| --- | --- |
| z18 の 1 タイル | 約 125m 四方(北緯 35°) |
| z18 の 1 マス | 約 7.8m 四方(北海道 約 6.8m、沖縄 約 8.6m) |
| 対象のマス数 | 日本の陸地 37.8 万 km² ÷ 61m² ≈ 約 62 億マス |
| 圧縮前 | 1 マス 4 バイトで約 25GB |
| SQLite(圧縮後) | **約 1〜2.5GB**(圧縮率 10〜25 倍と仮定。1 県で試作して実測する) |

- 道路 1 マスがおおむね実際の道幅(2 車線で 6〜8m)になる。
- 一戸建て(約 10m)は 1〜2 マス。隣の建物とつながって塊になりやすく、小さな建物は消える。
- 低ズーム用のピラミッド(集約済みデータ)は持たない。各ブロックに数バイトの代表値だけを持たせる(5 章)。

## 5. SQLite のスキーマ

ブロック 1 行 = **z18 の 256×256 マス**(z14 タイル 1 枚の範囲、約 2km 四方)。
ブロック 1 つが、ちょうど **z10 の 1 マス**に当たる。陸地を含むブロックは約 10 万行。

```sql
-- OSM の種別(マスの属性が参照する)
CREATE TABLE osm_class (
  id    INTEGER PRIMARY KEY,   -- 1〜255
  kind  INTEGER NOT NULL,      -- 0=面 1=道路 2=線路
  key   TEXT NOT NULL,         -- 'landuse' / 'highway' / 'railway' ...
  value TEXT NOT NULL,         -- 'farmland' / 'primary' / 'rail' ...
  rank  INTEGER NOT NULL       -- 優先度(面は重なったときの勝ち順、道路は幹線ほど大)
);

-- z18 のマス本体
CREATE TABLE block (
  bx        INTEGER NOT NULL,  -- = z14 タイル x
  by        INTEGER NOT NULL,  -- = z14 タイル y
  data      BLOB,              -- 256×256 マス × 4 バイト を zlib 圧縮。全マス同じ値なら NULL
  -- 代表値(z10 以下の動的生成用。data を展開せずに読める)
  area      INTEGER NOT NULL,  -- 最も多い面種別(osm_class.id)
  area_pct  INTEGER NOT NULL,  -- その割合 0〜100
  road      INTEGER NOT NULL,  -- ブロック内で最上位の道路(0=なし)
  rail      INTEGER NOT NULL,  -- ブロック内で最上位の線路(0=なし)
  motorway  INTEGER NOT NULL,  -- 高速道路を含むか(0/1)
  mount_pct INTEGER NOT NULL,  -- 山になるマスの割合 0〜100
  rock_pct  INTEGER NOT NULL,  -- 岩山になるマスの割合 0〜100
  PRIMARY KEY (bx, by)
) WITHOUT ROWID;

-- 元データの日付、ライセンス、ズーム(18)など
CREATE TABLE meta (key TEXT PRIMARY KEY, value TEXT);
```

### 5.1 1 マスの 4 バイト

| バイト | 内容 |
| --- | --- |
| byte0 | 面の種別(`osm_class.id`、kind=0) |
| byte1 | 一般道路の種別(kind=1。高速道路を除いて最上位のもの。0 = なし) |
| byte2 | 線路の種別(kind=2。0 = なし) |
| byte3 | bit0 = bridge、bit1 = cliff、bit2〜4 = 傾斜の段階(0〜7)、bit5 = 高速道路あり |

- 高速道路は byte1 に入れず、bit5 で持つ。高架の高速道路の下を一般道路がくぐるマスで、一般道路の情報を失わないため。

- 1 マスに複数の面が重なる場合は、`rank` の高いものを byte0 に入れる(例:住宅地の中の建物 → 建物)。
- 道路と線路は面と別のバイトなので、建物や農地の上を通っていても両方残る。
- `tunnel=yes` の道路・線路は格納しない(地上の地形を出す)。
- データベースに入れるのは OSM の種別まで。ゲームの地形への変換は実行時に行う(7 章)。

### 5.2 osm_class の例

| ゲームの地形 | kind | OSM のタグ |
| --- | --- | --- |
| 市街地 | 面 | `landuse=residential` / `commercial` / `retail` / `industrial` |
| 建物 | 面 | `building=*`(値は区別せず 1 行) |
| 砂地 | 面 | `natural=beach` / `sand` |
| 雪・氷 | 面 | `natural=glacier`(日本ではほぼ出ない) |
| 農地 | 面 | `landuse=farmland` / `orchard` / `meadow` |
| 森 | 面 | `landuse=forest`、`natural=wood` |
| 水 | 面 | `natural=water`、`waterway=riverbank`、`landuse=reservoir`、海(陸地ポリゴンの外側) |
| 湿地 | 面 | `natural=wetland` |
| 岩山 | 面 | `natural=bare_rock` |
| 山 | 面 | `natural=scree` / `shingle` |
| 草原 | 面 | 上記以外の面、何もない陸地 |
| 高速道路 | (byte3 bit5) | `highway=motorway` / `motorway_link`、`motorroad=yes` の道路 |
| 道路 | 道路 | `highway=trunk` 〜 `service`、`footway` / `path` / `steps` など(`access=private` / `no` も含む) |
| 線路 | 線路 | `railway=rail` / `subway` / `light_rail` / `tram` など |

## 6. 事前ビルド

1. `osmium tags-filter` で必要なタグだけを抜き出す。
2. `ogr2ogr` で EPSG:3857 の GeoPackage に変換する(面・道路・線路・cliff の 4 レイヤー)。
3. ブロックごとに GDAL でラスタライズする(256×256 マス)。
   - 面:マスの中心がポリゴンに入れば塗る。`rank` の低い順に塗って、高いものが上に来るようにする。
   - 海:陸地ポリゴンの外側を水にする。
   - 道路・線路・cliff:`ALL_TOUCHED=TRUE` で塗る。マスに少しでも線が通れば、そのマスに入る。
     斜めの線も上下左右につながる(4 連結)ので、上下左右にしか動けない NES でも歩ける。
   - 河川:`waterway=river` / `canal` の線も水として塗る。`stream` は塗らない(細い沢で道がふさがれるのを防ぐ)。
4. DEM10B を z18 のマスに再標本化して傾斜を求め、byte3 に段階として入れる。
5. 代表値の列を計算し、`data` を zlib 圧縮して書き込む。全マス同じならば `data` は NULL。

ブロックは約 10 万個で、互いに独立なので並列に処理できる。まず 1 県分の範囲で試作し、時間と容量を実測する。

## 7. 1 マスの地形の決め方

z18 のマス(またはまとめた範囲)について、上から順に判定する。

| 順 | 条件 | 地形 |
| --- | --- | --- |
| 1 | 同じ z18 のマスに道路と線路の両方がある | 踏切 |
| 2 | 道路があり、bridge フラグがある、または下が水 | 橋 |
| 3 | 一般道路がある | 道路 |
| 4 | 高速道路がある | 高速道路 |
| 5 | 線路がある(下が水でも) | 線路 |
| 6 | 面が建物 | 建物 |
| 7 | 面が水 | 水 |
| 8 | 面が湿地 | 湿地 |
| 9 | cliff フラグ、`natural=bare_rock`、または傾斜 45° 以上 | 岩山 |
| 10 | 自然地(森・草原・scree など)で傾斜 25° 以上、または `natural=scree` / `shingle` | 山 |
| 11 | それ以外 | 面の種別に対応する地形(5.2 の表) |

- 道路を岩山・湿地より先に判定するので、岩山の上の登山道(`highway=path`)や湿原の木道(`highway=footway`)は通れる。
- 湿地は通行不可。人が実際に通れない場所として、崖・急斜面・湿地を不可にする。
  施設・障壁・アクセス制限のタグは使わない。
- 高速道路と線路は、z14〜18 では通行不可。渡れるのは、一般道路と重なるマス(踏切・陸橋・高架下・ガード下)だけ。
  陸橋で線路をまたぐ道路も、z18 では同じマスに道路と線路があるので踏切になる(通れるので通行上は問題ない)。
- z13 以下では、線路と高速道路を通行可にする(見た目はそのまま)。低ズームでは踏切や高架下を判定できず、
  そのままだと地図が線路と高速道路で分断されるため。
- `access=private` / `no` の道路も通常の道路として扱う(通れる)。
- 山を傾斜で決めると、山の斜面の森は山になる。z18(約 8m のマス)では、平らな尾根や谷は森のまま残る。

### 7.1 道路・線路の向き

上下左右の隣のマスを見て決める。

- 道路:左右だけにつながる → 横、上下だけ → 縦、それ以外(T 字・十字・曲がり角)→ 交差点。
- 線路・高速道路:左右だけ → 横、上下だけ → 縦、それ以外 → 曲がり・分岐。
- 橋は道路と同じ規則で横/縦を決める。
- タイルの端の判定には隣のマスが要るので、要求された範囲より 1 マス広く読む。

## 8. ズームごとのマスの作り方

ズーム z の 1 マスは、z18 の 2^(18−z) × 2^(18−z) マスに当たる。ピラミッドは持たず、すべて実行時に集約する。

| z | 1 マス = z18 の | 読むもの | 作り方 |
| --- | --- | --- | --- |
| 18 | 1×1 | `data` | 7 章の判定をそのまま使う |
| 14〜17 | 2×2 〜 16×16 | `data`(1 タイルで 1〜4 ブロック) | 全マスを集約(8.1) |
| 11〜13 | 32×32 〜 128×128 | `data`(1 タイルで 4〜64 ブロック) | 全マスを集約。0.35 秒に収まらなければ面だけ間引く |
| 10 | 1 ブロック | 代表値の列 | 1 マス = 1 行 |
| 6〜9 | 2×2 〜 16×16 ブロック | 代表値の列(1 タイルで 1,024〜26 万行) | 代表値を集約(8.2) |
| 1〜5 | 32×32 ブロック以上 | 代表値の列を間引いて読む | 1 マスにつき数ブロックだけ読む |

z6 前後が 0.35 秒に収まるかは実測で確認する。間に合わなければ、間引きを使うズームの範囲を広げる。

### 8.1 data からの集約(z11〜17)

例:z17 の 1 マス = z18 の 2×2 マス(約 15.6m 四方)。z17 の 1 タイルは z18 の 32×32 マスで、1 ブロックの中に収まる。

1. **道路**:子マスのどれかに道路があり、その種別がズームのしきい値(8.3)以上なら道路にする。種別は最上位のもの。
   どれかにあれば残す(OR)ので、道路のつながりは崩れない。
2. **線路・高速道路**:道路と同じ処理(高速道路は byte3 の bit5 で OR)。
3. **踏切**:同じ子マスに道路と線路の両方がある場合だけ。別々の子マスにあるだけなら道路にする
   (並走している道路と線路を、まとめたときに踏切にしないため)。
4. **橋**:道路の子マスに bridge フラグがある、または子マスに水がある。
5. **岩山**:子マスのうち、7 章の 7 に当たるものの割合で決める(z17 では 1 つでもあれば)。
6. **面**:子マスの byte0 の多数決。同数なら `rank` の高い方。
   例:建物 2・住宅地 2 → 建物、建物 1・住宅地 3 → 市街地。
7. 7 章の順に地形を決め、7.1 で向きを決める。

### 8.2 代表値からの集約(z10 以下)

- 道路・線路:ブロックの `road` / `rail` がしきい値以上なら道路・線路にする(OR)。
- 岩山:`rock_pct` の平均が 30% 以上(案)。
- 山:`mount_pct` の平均が 40% 以上(案)。日本アルプスなどが山脈として見える。
- 面:`area` の多数決(`area_pct` で重みづけ)。
- 代表値には位置の情報がないので、z10 以下では踏切と橋は出さない(道路・線路として出す)。

### 8.3 ズームごとに出す道路・線路

| z | 一般道路 | 高速道路 | 線路(初期値) |
| --- | --- | --- | --- |
| 18 | すべて(`footway` / `path` / `steps` も含む。歩道 `footway=sidewalk`・横断歩道は除く) | 出す | すべて |
| 17 | `residential` 以上 | 出す | すべて |
| 16 | `tertiary` 以上 | 出す | すべて |
| 15 | `secondary` 以上 | 出す | すべて |
| 13〜14 | `primary` 以上 | 出す | `rail` / `subway` |
| 12 | `trunk` | 出す | `rail` / `subway` |
| 6〜11 | `trunk` | 出す | `rail` |
| 1〜5 | 出さない | 出さない | 出さない |

- 当初の表(15〜17 は `service` 以上、12〜14 は `tertiary` 以上、9〜11 は `primary` 以上、6〜8 は `trunk`)では、
  都心(東京駅・渋谷・豊洲)の画面で z12〜15 の道路マスが 60〜99% になり読めなかったため、3 段上げた。
  道路マスは z12〜16 で 19〜53%、z11 で 26〜29%(z10 以下は未測定)(東京 3 地点の実測)。
- 実装は `server/osmsource.ts` の `ROAD_MIN` / `RAIL_MIN`。地方での見え方は未確認。

## 9. 地形の種類を増やす(ROM 側の変更)

既存の 10 種に次の 13 種を足して、23 種にする。

| 地形 | 通行 | パレット(案) |
| --- | --- | --- |
| 市街地 | 可 | 灰 |
| 建物 | 不可 | 灰 |
| 砂地 | 可 | 茶/白 |
| 雪・氷 | 可 | 茶/白 |
| 農地 | 可 | 緑 |
| 湿地 | 不可 | 緑 |
| 線路(横) | 不可 | 灰 |
| 線路(縦) | 不可 | 灰 |
| 線路(曲がり・分岐) | 不可 | 灰 |
| 踏切 | 可 | 灰 |
| 高速道路(横) | 不可 | 灰 |
| 高速道路(縦) | 不可 | 灰 |
| 高速道路(曲がり・分岐) | 不可 | 灰 |

- 線路・高速道路の曲がり・分岐がないと、斜めに走る線が途切れて見える。
- 通行不可は水・岩山・建物・湿地・線路・高速道路(線路・高速道路は z14 以上のみ)。
  建物が不可なので、街中は道路沿いにしか歩けない。
- 通行判定(`probe_run`)は z によって変わる(z13 以下では線路・高速道路を通す)。
- 作業:`gfx/gen_chr.ts` に絵を足す、`src/terrain.h` とサーバーの ID を一致させる、
  `src/main.c` の `tile_pal[]` と通行判定(`probe_run`)を更新する。
- 容量:BG は 64 メタタイルまで入るので 23 種は問題ない。パレットは 4 つ(緑・茶/白・灰・青)にまとめ、
  同じパレットの 3 色で描き分ける。道路・建物・市街地・線路・踏切・高速道路がすべて灰になるので、絵の形で区別する。

## 10. 決めたいこと

決定済み:

- **ズームの上限は z18**。ROM の `Z_MAX`(`src/main.c`)とサーバーの `Z_MAX`(`server/mapserver.ts`)を 20 → 18 に下げる。
  座標は 24bit のまま(z18 では上位 2bit が常に 0)。
- **日本の範囲外**(`block` に行がない場所)は水を返す。
- **高速道路**は通行不可の地形として描く。一般道路と重なるマスは一般道路を優先する。
- **線路**は通行不可。踏切(一般道路と重なるマス)だけ通れる。
- **`access=private` / `no` の道路**は通常の道路として扱う。
- **湿地**(`natural=wetland`)は通行不可の新しい地形。木道などの道路は通れる。
  施設・障壁・アクセス制限のタグでは通行不可にしない。
- **低ズーム**:z13 以下では線路・高速道路を通行可にする。
- **傾斜**:山は 25° 以上、岩山は 45° 以上。
- **一般道路**:8.3 の表のとおり。

未決:

1. **しきい値**:8.2 の山・岩山の割合(初期値 40% / 30%)、8.3 の線路の種別(初期値)。
