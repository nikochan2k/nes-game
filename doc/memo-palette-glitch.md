# メモ: 歩くと、マスごとのパレットがずれる件(再発したときの手順)

ユーザーから「地図が化ける」と再発の連絡があったら、このメモの手順で調べる。
2026-11 に一度調べて、原因を特定できないまま止まっている。ここには、**分かったこと・分かっていないこと・次にやること**を残す。

## 1. 症状

- Mesen で ROM を動かし、地図サーバーにつないだ状態で歩くと、**同じ地形の絵が、マスごとに違うパレット(色)で出る**。
  (例: 同じ「線路の交差」の絵が、灰色・茶・緑・青のマスに混ざる。)
- **タイルの形(絵)は正しい**。地形 ID は正しく、色(属性テーブル)だけがばらつく。
- 観測した画面(2026-11-04、地形が 23 種だった時期のスクリーンショット)を、絵×パレットに分解して集計した結果:
  線路の交差(期待 pal2)が pal1 に 18 マス、高速道路の交差(期待 pal2)が pal0 に 52・pal1 に 27・pal2 に 15・pal3 に 6 マス、
  水(期待 pal3)が pal0 に 6・pal1 に 5・pal2 に 4 マス。つまり、期待のパレットに揃わず、散らばる。
- その後、地形を作り直した(32 種、パレットの割り当ても変更)。**今も起きるかは未確認**。再発の連絡が、その確認になる。

## 2. これまでに確認したこと(正常だったもの)

| 確認したこと | 結果 |
| --- | --- |
| サーバーの応答(関東の実 DB で、歩行を模した 10,800 件の要求) | 例外 0、結果の不一致 0、範囲外 ID 0。要求の切り方(行・列・1 マス)で結果は変わらない |
| ROM の `queue_cell`(属性テーブルの合成)を JS で再現し、実座標(東京 z10)の 19×17 マスに当てた | 属性から読み戻したパレットが期待と**全 323 マス一致** |
| ROM の `tile_pal[]`(地形 ID → パレット)の中身(ROM バイナリを直接確認) | 当時の全 23 要素が正しい。後続の `palette[]` の直前に収まっている |
| ROM の RAM 使用量 | `$0300〜$04B0`(上限 `$05FF`)。あふれていない |
| iNES ヘッダ | 4 画面ミラー(`$08`)。属性テーブルの配置(`$23C0`/`$27C0`/`$2BC0`/`$2FC0`)は 4 枚分ある |
| vblank の時間(`flush_cells` + `probe_run` + `apply_scroll`) | `probe_run` は約 120 サイクルで小さい。ただし**実機のサイクル数は未計測** |
| 地図サーバーが落ちていないか | 要求ログに例外なし。リセットでブリッジを接続し直すと、関東の地図が出る |

## 3. 分かっていないこと(原因の候補)

**PPU に実際に入っている属性テーブルとパレット RAM の中身を、まだ見ていない。** ここが分かれば、原因が大きく絞れる。

| 候補 | 何を意味するか | 確かめ方 |
| --- | --- | --- |
| A. PPU の属性バイトそのものが違う | ROM のキュー・`attr_shadow`・`flush_cells`(`src/ppu.s`)の書き込みのバグ | PPU ダンプで、マスごとの属性のパレットを `tile_pal` と比べる(4 章) |
| B. 属性は正しいが、表示が違う | PPU の描画中に書き込んでいる(タイミング)、またはエミュレータの扱い | PPU ダンプは一致するのに画面がずれる → 候補 C・D |
| C. vblank を超えて PPU を書いている | `flush_cells` → `probe_run` → `apply_scroll` が vblank(約 2,270 サイクル)に収まらず、スクロール・属性の書き込みが描画中にずれる | `$2005` / `$2007` への書き込み時の走査線を記録する(5 章) |
| D. パレット RAM の中身が違う | `$3F00〜` の色が、`palette[]` と違う(書き込みの取り違え) | PPU ダンプのパレット RAM の行を、`src/main.c` の `palette[]` と比べる |
| E. 4 画面ミラーの扱い | 使っているエミュレータの版で、4 画面 VRAM の属性が正しく動かない | 別の設定・別の版で再現するか |
| F. リング VRAM の古いマスの属性 | `reload_world`(ズーム変更)で、`attr_shadow` の控えと PPU の実際の値がずれる | ズーム直後・歩き始めの画面を、ダンプで調べる |

## 4. 再発したときの手順(診断ツールは `mesen/` と `server/` に入っている)

環境の注意: macOS の画面収録の権限がなく、私は他アプリのウィンドウを撮れない。Mesen のスクリーンショット機能
(保存先 `~/Library/Application Support/Mesen2/Screenshots/`)と、Mesen の Lua でメモリを送る方法を使う。

1. **再現**: `make server`(または `bun server/mapserver.ts -v`)→ `make bridge`。Mesen のスクリプトのネットワーク許可
   (`~/Library/Application Support/Mesen2/settings.json` の `AllowNetworkAccess`)が `true` であること(私は書き換えを拒否される。ユーザーが
   `sed` などで直す)。スクリプトを読み込んだら**ゲームをリセット**する(最初の要求が接続前に出ると、ROM は内蔵の簡易生成に切り替わる)。
   `lsof -nP -iTCP:5555` でブリッジの接続(`ESTABLISHED`)を確かめる。サーバーのログに要求が流れるのが、つながっている印。
2. **ユーザーに頼むこと**: 化けた状態で、(a) Mesen のスクリーンショットを撮る、(b) スクリプトウィンドウ(Debug → Script Window)を
   **もう 1 つ**開き(ブリッジのウィンドウとは別)、`mesen/dump_ppu.lua` を実行する。
3. **PPU のダンプ**: 先に `bun server/ppu_dump.ts` を起動して待ち受ける(`127.0.0.1:5560`)。Lua を実行すると、パレット RAM・4 枚の
   ネームテーブル・属性テーブルが送られ、`data/ppu_dump.txt` に保存され、**マスごとの属性のパレットが `tile_pal` と合っているか**を集計して出す。
   期待値(`tile_pal`)と色の表は、`src/main.c` から読むので、地形を足しても食い違わない。
4. **画面から調べる**: `bun server/shot_palette.ts "<スクリーンショット.png>"`。マスの区切りのずれを総当たりで探し、各マスが
   「どの地形の絵 × どのパレット」に完全一致するかを集計する。期待のパレットと違うものに `← パレットがずれている` が付く。
   注意: 色 `21` / `28` / `38` / `16` の RGB は**近似**(スクリーンショットで確かめていない)。一致が極端に少なければ、色の表を直すか、PPU ダンプを使う。
5. **結果の読み方**:
   - ダンプの属性が `tile_pal` と**食い違う** → 候補 A・F。属性の書き込み(`queue_cell`、`attr_shadow`、`src/ppu.s` の `flush_cells`、
     `reload_world`)を、ダンプの「例:」の行(座標・期待・実際・属性バイト)から逆算する。
   - ダンプは**一致するのに画面がずれる** → 候補 B・C・E。5 章のタイミング測定へ。
   - パレット RAM の行が `palette[]` と違う → 候補 D。

## 5. タイミングを測る(候補 C)

vblank に収まっているかを、Mesen の Lua で測る。`$2005` / `$2006` / `$2007` への書き込みのたびに、走査線とサイクルを記録する。
(`emu.addMemoryCallback(関数, emu.callbackType.write, 0x2005)` の中で `emu.getState()` から PPU の走査線を読む。状態のキー名は Mesen の版で違うので、
最初に `emu.getState()` の中身を出して確かめる。)書き込みが走査線 241(vblank の始まり)から大きく離れた、または描画中(走査線 0〜239)にあれば、vblank の超過。
対策は、`CELLS_PER_FRAME`(1 フレームで積むマス数)と `QCELLS`(キューの長さ)を減らす、`probe_run` の処理を vblank の外へ出す、など。

## 6. 参考

- 診断ツール: `mesen/dump_ppu.lua`(Lua)、`server/ppu_dump.ts`(受け取りと集計)、`server/shot_palette.ts`(画面の集計)、
  `server/romtables.ts`(ROM の表の読み込み)。
- ROM の属性の合成: `src/main.c` の `queue_cell`(属性 1 バイトに 4 マスぶんの 2bit)、書き込みは `src/ppu.s` の `flush_cells`、
  控えは `attr_shadow[]`(256 バイト)。属性のアドレス: `$23C0 + nt*0x400 + ab`(`ab = (ly>>1)*8 + (lx>>1)`)、
  ビット位置は `((ly & 1) << 2) | ((lx & 1) << 1)`(左上 0、右上 2、左下 4、右下 6)。
- `--testrunner`(Mesen のヘッドレス実行)は、試したが出力も接続もなく動かなかった。使わない。
- 仕様書は `doc/map-spec.md`。
