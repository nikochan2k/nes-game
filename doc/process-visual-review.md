# 手順書: 見栄えの確認(地図の生成・反映の前に、ブラウザで確認する)

## 1. 決まり(標準)

**地図の見え方が変わる変更は、地図の生成(DB の作り直し)や ROM・サーバーへの反映の前に、ブラウザで見栄えを確認し、
ユーザーの承認を得てから反映する。**

理由: 反映のやり直しが重いため。DB の作り直しは、関東全域で約 6 分(メモリ圧迫のときは約 50 分)かかり、
ROM の絵や ID を変えると、ROM・サーバー・DB が連動して変わる。見栄えは、画像で見るまで判断できず、
実際に「線路が階段状」「駅が出ない」「市街地が質素」といった指摘を、反映後に受けて、何度もやり直した。

この決まりは、`CLAUDE.md` にも書いてあり、作業するエージェントも従う。

## 2. 適用範囲

**対象**(見た目が変わるもの。迷ったら対象にする):

- タイルの絵(`gfx/gen_chr.ts`)、パレット(`src/main.c` の `palette[]` / `tile_pal[]`)、地形の種類・統合・分割・ID
- 地形の判定規則(`server/osmsource.ts`)、線路の向き(`server/rail.ts`)、ズーム別のしきい値(`ROAD_MIN` / `RAIL_MIN` など)
- データの塗り方(`server/rasterize.ts`、`server/worldbuild.ts`: 線の太さ・連結、細線化、市街地の補完、駅のマスの位置など)
- 面や道路の分類(`server/worlddb.ts` の `CLASSES`、`server/osmfeatures.ts`)

**対象外**(出力が変わらないもの。性能改善・内部の整理・テスト・ドキュメント・データの取得):
出力が変わらないことは、変更の前後の DB で `bun server/preview.ts --before` を使って確かめるとよい。

**省略できる場合**: ユーザーが「確認せずに反映して」と明示したとき。省略したことは、報告で述べる。

## 3. 標準の手順

### 手順 1: 案を作る(まだ反映しない)

- **絵・パレットの案**: 候補の絵を、実機と同じ 16×16・同じパレットで描いた画像にする。複数案は並べる。
  タイルを敷き詰めた画像(街らしさ)や、組み合わせの見本(線路の輪・斜め・曲線など)も添える。
  全タイルの一覧は `make preview`(`tiles.png`)で出る。
- **塗り方・判定の変更**: 変更後の出力を、基準地点で見られるようにする。**`make sample`** を使う。
  - `bun server/build_world.ts sample`: 基準地点(`server/spots.ts`。起動位置・東京駅・豊洲・奥多摩・房総南端・熊谷・筑波山)の周り
    (±0.02°、約 1.7×2.2 km)だけの小さな DB `data/sample.sqlite` を、PBF の 1 回の読み込みで作る(約 1〜2 分。全体は約 6 分)。
    本番の `data/world.sqlite` は上書きしない。続けて、同じ地点を航空写真と並べて描き、ブラウザで開く(`make sample` はこの 2 つを続けて行う)。
  - 変更前と並べる: `bun server/preview.ts --db data/sample.sqlite --before <変更前の DB>`(変更前の DB が古いときは、変更前のコードで `sample` を作る)。
  - **全体の生成(約 6 分)は、この確認で承認を得てから行う**。確認の前に全体を作ると、やり直しで時間を無駄にする。
  - 地点を足すときは、`server/spots.ts` の `DEFAULT_SPOTS` を直す(変更の種類に応じて、操車場のある駅や入り組んだ海岸など)。
- **データを使わない変更**(合成のケース): 角度の違う直線、円弧、T 字、太い帯などの合成データを、旧方式と新方式で描き分けて並べる。
  実データで再現しにくい問題(複線、曲線)に有効。

### 手順 2: 自分で見て、欠陥を直してから出す

- 作った画像を、自分で `Read` して確認する。途切れ、ぎざぎざ、二重の線、色の誤り、絵の継ぎ目などがあれば、直してから出す。
  ユーザーに見せる前に、自分で見つけられる欠陥は、自分で直す。
- 数値で補強できるものは、数値も出す(例: 「3 方向以上につながるマス」の数、各ズームの応答時間)。

### 手順 3: ブラウザで開いて、ユーザーに提示する

- `make preview`(または `bun server/preview.ts --open`)で、`data/compare/preview.html` をブラウザで開く。
  案の比較ページ(`proposal.html` など)を作るときも、`data/compare/` に置いて `open` で開く。
- 提示では、必ず次を述べる: 「**まだ反映していません**」、何が悪かったか、何を変える案か、**決めたいこと**、反映するときの作業と時間。
- 画像は実機(Mesen)の表示そのものではない。色の近似(`UNVERIFIED_COLORS`)があることも、ページに書いてある。

### 手順 4: 選択肢は `AskUserQuestion` で聞く

- 案の選択(A/B/C)や、方式の可否は、`AskUserQuestion` で聞く。承認を得るまで、反映しない。
- ユーザーが「もう少し考えて」と言えば、手順 1 に戻る。

### 手順 5: 承認された案を反映する

- ROM(`gfx/gen_chr.ts`、`src/*`)、サーバー、ビルダーを変更し、テストを通す(`make test`、`bunx tsc --noEmit -p .`、`make`)。
- ID を変えるときは、`src/terrain.h`、`server/terrain.ts`、`gfx/gen_chr.ts`、`src/main.c` の `tile_pal[]` を同時に直す。

### 手順 6: 地図を生成する(`make sample` の承認の後)

- DB は別ファイルに作ってから差し替える(動作中のサーバーが、元のファイルを開いたままのため)。
  差し替えたら、サーバーを再起動する。ビルドの経過は、ログの最後の行とプロセス(`ps`)で確認する
  (見張りのコマンド自身が、検索文字列に引っかからないように注意)。

### 手順 7: 実際の地図で確認する

- 同じ基準地点で、航空写真と地図を並べて確認する(`make preview`)。問題があれば、手順 1 に戻る。
- 実機(Mesen)での表示は、ユーザーが確認する(`make bridge`。ゲームをリセットする)。

### 手順 8: 仕様書を更新し、コミットする

- 見た目や規則が変わったら、`doc/map-spec.md` を更新する。
- コミットは、ユーザーが頼んだときだけ行う。

## 4. 基準地点

`make preview` は、次の地点を描く(`server/preview.ts` の `DEFAULT_SPOTS`)。`--spots` で変えられる。
`data/start.json` があれば、その位置も先頭に加わる(自宅付近など。`data/` は `.gitignore` なのでコミットされない)。

| 地点 | 確かめること |
| --- | --- |
| 起動位置(`data/start.json`) | ユーザーが実際に見る場所。駅(起動位置が駅なら、◎ が中心に出るか) |
| 東京駅 | 都心の密度、道路・建物・線路・駅 |
| 豊洲 | 海岸、水、橋、埋め立て地 |
| 奥多摩 | 山・岩山・森の自然さ |
| 房総南端 | 海岸と森 |
| 熊谷 | 平野(農地・草・市街地) |
| 筑波山 | 孤立した山 |

変更の種類に応じて、地点を足す(線路を変えたら、操車場のある駅。海岸線を変えたら、入り組んだ海岸)。

## 5. 見るポイント(チェックリスト)

- **線路**: 一筆書き(分岐点以外は 1 本の鎖)か。階段状・ぎざぎざ・途切れ・二重の線がないか。斜めと曲線がなめらかか。
- **駅**: 出るか。1 つの駅に 1 マスか。線路の近くにあるか。
- **市街地・建物**: 質素すぎないか(色・屋根)。敷き詰めたとき、繰り返しの模様が目立ちすぎないか。
- **道路**: 画面を占める割合が高すぎないか(目安: 画面の 20〜50%)。
- **山・岩山・森**: 並べたとき、模様が縞状にならないか。海岸・水辺が自然か。
- **色**: 近似の色(`UNVERIFIED_COLORS`)が実機でどう見えるかは、実機で確認するまで分からない。
- z17 と z18 の**両方**を見る(NES の画面は z17 で約 250m 四方、z18 で約 125m 四方)。
- 航空写真と**位置・形**が合っているか。OSM に描かれていないもの(点だけの駅、細い路地)は、地図に出ないのが正しい。

## 6. 道具と置き場所

| 道具 | 内容 |
| --- | --- |
| `make sample` | 基準地点の周りだけの小さな DB(`data/sample.sqlite`)を作り、見栄えの確認ページを開く。**全体の生成の前に必ず行う** |
| `make preview` | 見栄えの確認ページ(`data/compare/preview.html`)を作って開く(`data/world.sqlite` を描く) |
| `bun server/preview.ts [--db] [--before] [--spots] [--out] [--no-photo] [--open]` | 同じ。DB や地点を指定できる |
| `server/png.ts`、`server/romtables.ts` | PNG の書き出し、ROM のパレット・色の表(絵は `gfx/tiles.chr`) |
| `data/compare/` | 確認用の画像とページの置き場所(`.gitignore`。コミットしない) |

- 航空写真は、国土地理院の「シームレス空中写真」(`cyberjapandata.gsi.go.jp`)。出典の表示が要る。取得は 1 枚ずつ、間隔をあけ、取得済みは取り直さない。
